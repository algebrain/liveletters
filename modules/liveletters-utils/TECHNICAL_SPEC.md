# `liveletters-utils` TECHNICAL_SPEC

## Назначение

`liveletters-utils` — общий крейт для небольших чистых функций и типов, которые должны одинаково работать во всех слоях проекта.

Крейт намеренно не содержит бизнес-логики LiveLetters. Его задача — убрать повторение простых проверок и форматирования из протокола, синхронизации, команд и тестов.

## Зона ответственности

- простая проверка формы почтового адреса;
- извлечение локальной части адреса;
- разбор и форматирование протокольной идентичности `Nickname <email>`;
- проверка непустых строк;
- перевод `SystemTime` в секунды Unix.

## Что крейт не должен делать

- зависеть от `liveletters-store`, `liveletters-protocol`, `liveletters-mail` или командных крейтов;
- открывать файлы, базы данных или сетевые соединения;
- знать про текущего пользователя, домашний каталог или настройки;
- содержать правила синхронизации, подписок, ленты или отображения постов;
- выполнять полный разбор почтовых адресов по почтовым стандартам.

## `email`

Функции `looks_like_email` и `email_local_part` используют одинаковую простую проверку адреса:

- внешние пробелы перед проверкой незначимы;
- внутри адреса не должно быть пробелов;
- должна быть ровно одна `@`;
- локальная часть и домен не должны быть пустыми.

Этого достаточно для текущих пользовательских адресов и протокольных идентичностей. Если в будущем понадобится полная поддержка сложных адресов, её нужно добавлять явно и покрывать отдельными тестами.

## `protocol_identity`

`ProtocolIdentity` — внутренняя типизированная форма для строк протокола:

```text
Alice <alice@example.com>
```

В JSON протокола `origin` и `source` остаются строками. Это делает сообщения читаемыми вручную, а Rust-код получает безопасный тип после разбора.

Правила:

1. `parse` принимает только форму с угловыми скобками.
2. В имени и адресе запрещены вложенные `<` и `>`.
3. Хвост после закрывающей `>` должен быть пустым или состоять только из пробелов.
4. Имя и адрес обрезаются по краям.
5. Канонический вывод: `Nickname <email>`.
6. Сериализация в JSON даёт строку, а не объект.

Поле `origin` обозначает первичный источник сообщения. Поле `source` обозначает непосредственный источник доставки. Оба поля используют этот же строковый формат.

## `text`

`require_non_blank` только проверяет непустоту после `trim()`. Она не изменяет значение и возвращает исходную ссылку, чтобы вызывающий код сам выбирал, нужно ли сохранять пробелы.

Ошибка `NonBlankError` содержит имя поля. Это помогает строить понятные ошибки без привязки к конкретному модулю.

## `time`

`unix_secs` нужен для одинакового поведения при переводе времени в секунды Unix. Значения до эпохи Unix превращаются в `0`, чтобы вызывающему коду не приходилось каждый раз обрабатывать ошибку `SystemTimeError`.

`unix_now` — тонкая обёртка над `SystemTime::now()` и `unix_secs`.

## Зависимости

- `serde` — сериализация и десериализация `ProtocolIdentity`;
- `thiserror` — типы ошибок.

Крейт не зависит от других крейтов LiveLetters.

## Тесты

Интеграционные тесты проверяют рантаймовое поведение:

- `tests/email.rs` — принятие простой формы адреса, отбрасывание пустых частей и пробелов внутри, извлечение локальной части;
- `tests/protocol_identity.rs` — разбор, канонический вывод, ошибки формата, сериализация и десериализация JSON;
- `tests/text.rs` — проверка непустых строк без изменения исходного значения;
- `tests/time.rs` — перевод времени в секунды Unix и обнуление времени до эпохи Unix.
