# Учебник по команде `lltt`

`lltt` — локальный интерфейс командной строки для личного блога с федерацией
по электронной почте. Все данные хранятся в домашнем каталоге, синхронизация
с другими узлами идёт через IMAP и SMTP. Этот документ — практическое
руководство: после прохождения шагов вы сможете инициализировать `lltt`,
создать и настроить идентичности, написать пост и комментарий, подписаться
на чужой блог, настроить почтовый обмен и прочитать входящее.

## 1. Обязательная начальная настройка

Нормальная работа с `lltt` невозможна, пока не выполнены четыре шага:

1. `lltt init` — подготовить домашний каталог;
2. `lltt user init <имя>` — создать черновик идентичности;
3. отредактировать черновик в обычном редакторе;
4. `lltt user add <имя>` и `lltt cu <имя>` — добавить идентичность и
   выбрать её текущей.

Минимальный пример для пользователя `alice`:

```sh
lltt init
lltt user init alice
nano ~/.liveletters/drafts/alice.toml
lltt user add alice
lltt cu alice
```

На Windows вместо `nano` откройте черновик в Notepad (Блокноте):

```powershell
notepad "$env:USERPROFILE\.liveletters\drafts\alice.toml"
```

После `lltt user init alice` файл `~/.liveletters/drafts/alice.toml`
нужно обязательно открыть и исправить. В нём надо заменить примерные
адреса, имя, почтовые серверы и пароли на ваши реальные параметры.
Если добавить черновик без правки, `lltt` сохранит демонстрационные
значения, и почтовая синхронизация работать не будет.

После успешного `lltt cu alice` можно выполнять команды, которым нужен
текущий пользователь: `lltt status`, `lltt post new`, `lltt feed`,
`lltt sync` и другие.

## 2. Прежде чем начать

Вам нужны:

- установленный `lltt` (введите `lltt --version`; если команда не найдена,
  обратитесь к сопровождающему вашей сборки);
- терминал с поддержкой UTF-8;
- любой почтовый ящик с доступом по IMAP и SMTP, если вы хотите проверить
  сетевую синхронизацию.

По умолчанию `lltt` хранит данные в `~/.liveletters`. Для экспериментов
можно (но не обязательно) выбрать другой каталог:

```sh
mkdir -p "$HOME/lltt-demo"
export LIVELETTERS_HOME="$HOME/lltt-demo"
```

Если `LIVELETTERS_HOME` задан, все дальнейшие пути будут внутри этого
каталога. Например, черновик Алисы будет лежать не в
`~/.liveletters/drafts/alice.toml`, а в
`$LIVELETTERS_HOME/drafts/alice.toml`.

## 3. Инициализация каталога

Команда `lltt init` создаёт базу данных, ключ для скрытия паролей,
каталог идентичностей, каталог черновиков и каталог `users/` для
отдельных локальных состояний пользователей.

```sh
lltt init
```

В ответ команда печатает отчёт и завершается без ошибок. Если каталог
уже не пуст, `init` откажется работать. Чтобы разрешить инициализацию
непустого каталога без удаления существующих файлов, добавьте флаг
`--force`:

```sh
lltt init --force
```

Сразу после инициализации команды, которым нужен текущий пользователь,
ещё не работают:

```sh
lltt status
# ошибка: текущий пользователь liveletters не задан: файл .../current-user отсутствует
```

Это нормально: `init` не создаёт пользователя. Следующий обязательный
шаг — `lltt user init <имя>`.

## 4. Идентичности и текущий пользователь

В `lltt` есть понятие «идентичность» — это один автор с одним почтовым
адресом, под которым вы публикуете записи. В любой момент времени одна
из идентичностей выбрана как **текущий пользователь liveletters**: именно
от её имени создаются посты, комментарии и подписки.

Важно: конфиги пользователей лежат вместе в `identities/`, но локальные
БД разделены. Для пользователя `alice` рабочее состояние находится в
`~/.liveletters/users/alice/` или `$LIVELETTERS_HOME/users/alice/`.
Если в одном домашнем каталоге есть `alice` и `bob`, они не видят посты
друг друга напрямую через общую БД; обмен должен пройти через почту.

Для управления списком идентичностей используется команда `lltt user`.
Команда `lltt cu` отвечает только за текущего пользователя: показать
его, выбрать другого или показать сведения о выбранном.

### 4.1. Создание черновика идентичности

Идентичность описывается файлом в формате TOML. Удобнее не писать его
с нуля, а создать черновик:

```sh
lltt user init alice
```

Команда создаст файл `~/.liveletters/drafts/alice.toml`, если
`LIVELETTERS_HOME` не задан. Если вы выбрали другой домашний каталог,
файл будет создан по пути `$LIVELETTERS_HOME/drafts/alice.toml`.

Откройте этот файл в редакторе и замените примерные значения на свои:

```sh
nano ~/.liveletters/drafts/alice.toml
```

На Windows откройте файл в Notepad (Блокноте):

```powershell
notepad "$env:USERPROFILE\.liveletters\drafts\alice.toml"
```

Пример содержимого после правки:

```toml
account_id    = "acct_alice"
display_name  = "Алиса"

[mail]
publish  = "alice@blog.example.org"
receive  = ["alice@blog.example.org"]

[mail.smtp]
host = "smtp.blog.example.org"
port = 587
security = "starttls"
username = "alice@blog.example.org"
password = "секрет-без-кавычек"
pwd_obfuscate = true
hello_domain = "blog.example.org"

[mail.imap]
host = "imap.blog.example.org"
port = 993
security = "tls"
username = "alice@blog.example.org"
password = "секрет-без-кавычек"
pwd_obfuscate = true
mailbox = "INBOX"

[meta]
resources_owned  = ["alice@blog.example.org"]
subscriptions    = []
```

Здесь:

- `account_id` — локальный служебный идентификатор в вашей установке;
- `display_name` — имя, под которым вас будут видеть читатели;
- `mail.publish` — адрес блога, на который подписываются другие;
- `mail.receive` — адреса, на которые вам приходят письма от подписчиков;
- `mail.smtp` и `mail.imap` — параметры отправки и приёма почты;
- `pwd_obfuscate = true` — указание скрыть пароль при добавлении
  идентичности;
- `meta.resources_owned` — перечень адресов, принадлежащих автору.

### 4.2. Добавление идентичности

После правки черновика добавьте его:

```sh
lltt user add alice
```

Без `--from` команда берёт стандартный путь:
`<домашний каталог>/drafts/alice.toml`. Если TOML лежит в другом месте,
укажите путь явно:

```sh
lltt user add alice --from /путь/к/alice.toml
```

Если в черновике заполнены SMTP- или IMAP-пароли и включено
`pwd_obfuscate`, команда отдельно попросит подтвердить каждый пароль.
Ввод скрытый: на экране видны только звёздочки. После успешного
добавления открытые пароли в черновике заменяются значениями вида
`obf:v1:...`.

Команда печатает `добавлен identities/alice.toml` и завершается. Она
не выбирает пользователя текущим автоматически.

### 4.3. Выбор текущего пользователя

Чтобы работать от имени Алисы, переключитесь:

```sh
lltt cu alice
```

Команда печатает `текущий пользователь: alice`. После этого все
команды публикации будут использовать её адрес блога.

Проверьте, что базовые команды теперь работают:

```sh
lltt status
lltt doctor
lltt cu show
```

`lltt status` на пустой базе печатает:

```
постов: 0
комментариев: 0
отложенных: 0
исходящих: 0
последняя активность: нет активности
```

### 4.4. Какие идентичности уже есть

```sh
lltt user list
```

После `init` список пуст: пользователь по умолчанию не создаётся.
После `lltt user add alice` в списке появится `alice`.

### 4.5. Кто выбран сейчас

```sh
lltt cu
```

Команда без аргументов печатает имя текущей идентичности. Пока никто
не выбран, она вернёт ошибку с подсказкой создать пользователя через
`lltt user init`, добавить через `lltt user add` и затем выбрать через
`lltt cu <имя>`.

### 4.6. Просмотр сведений об идентичности

```sh
lltt user show alice
```

Эта команда пригодится после добавления пользователя. Она печатает
содержимое идентичности: имя для отображения, служебный идентификатор
учётной записи, адрес блога, список адресов для входящей почты и список
ресурсов во владении. Пароли в почтовых секциях маскируются звёздочками.

### 4.7. Удаление идентичности

```sh
lltt user rm alice --yes
```

Команда требует явного подтверждения флагом `--yes`. Удалить ту
идентичность, которая выбрана сейчас, нельзя — сначала переключитесь
на другую:

```sh
lltt user rm alice --yes
# ошибка: нельзя удалить текущую идентичность `alice`; сначала переключитесь
```

## 5. Настройки пользователя и почты

Идентичность отвечает на вопрос «кто пишет». Настройки отвечают на
вопрос «как `lltt` ведёт себя». Это два разных слоя: `lltt user`
управляет идентичностями, `lltt cu` выбирает текущего пользователя,
`lltt settings` точечно меняет настройки в базе данных.

Для разовых правок удобна короткая форма: вместо `lltt settings set <ключ> <значение>` можно писать `lltt set <ключ> <значение>`. Обе формы делают одно и то же.

### 5.1. Просмотр настроек

```sh
lltt settings
```

Команда печатает две секции: `[user_settings]` (профиль пользователя)
и `[mail_settings]` (параметры IMAP и SMTP). После первой инициализации
секция `[user_settings]` отсутствует — её нужно создать первой записью.

### 5.2. Базовый профиль пользователя

```sh
lltt set nickname      alice
lltt set email_address alice@blog.example.org
```

Каждая команда печатает `настройка обновлена: <ключ>`. Всего допустимы
пять пользовательских ключей:

- `nickname` — короткое имя для отображения;
- `email_address` — основной адрес электронной почты;
- `avatar_url` — ссылка на аватар (пустая строка означает «нет
  аватара»);
- `language` — язык писем, которые `lltt` генерирует для подписчиков
  (если значение не задано, выбирается по языку системы);
  подробности — в разделе 5.5;
- `setup_completed` — флаг завершения первоначальной настройки
  (`true` или `1` означает «готово»).

Проверить, что записалось:

```sh
lltt settings
```

### 5.3. Параметры почты

Для `sync pull` (IMAP) и `sync push` (SMTP) нужны оба блока. Основной
путь — заполнить их в черновике из `lltt user init` и добавить
идентичность через `lltt user add`: тогда настройки почты будут
сохранены в `[mail_settings]` автоматически.

Позже удобно точечно поправить одно поле короткой формой:

```sh
lltt set smtp.host      smtp.blog.example.org
lltt set imap.mailbox   Archive
```

#### Окно первого sync

Настройка `imap.initial_lookback_days` управляет тем, как глубоко
в историю заглядывает `lltt sync` при самом первом запуске.
По умолчанию `1` (только сегодняшние письма). На большом ящике
первый запуск без этой настройки может занять заметное время,
потому что клиент будет перебирать всю почту с UID 1.

```sh
lltt set imap.initial_lookback_days 7
```

Допустимо целое неотрицательное число суток. `0` — с самого начала
(UID 1). Отрицательные и нечисловые значения отклоняются.
После первого запуска настройка больше не применяется; sync
работает по сохранённому курсору. Чтобы подтянуть прошлое позже,
используйте `lltt sync backfill --days=N`.

Допустимые значения параметров `*.security`: `none`, `starttls`, `tls`,
`ssl`. Значение `ssl` или `SSL` означает то же, что `tls`: защищённое
соединение сразу при подключении.
Пароли сохраняются в защищённом виде и при просмотре через
`lltt settings` маскируются звёздочками.

```sh
lltt settings
```

### 5.4. Если ключ неизвестен

`lltt set` (и полная форма `lltt settings set`) принимает только ключи из списка выше. Постороннее имя вызовет ошибку:

```sh
lltt set unknown.key value
# ошибка: неизвестный ключ: unknown.key
```

### 5.5. Язык писем

Письма, которые `lltt` рассылает подписчикам и контрагентам
(новые записи, комментарии, уведомления о подписке), собираются
на выбранном языке. Язык берётся из настройки `language` —
отдельного поля профиля пользователя.

```sh
lltt set language en
# настройка обновлена: language

lltt set language ru
# настройка обновлена: language
```

В настоящий момент поддерживаются только два значения: `ru` и `en`.

### Как выбирается язык, если вы ничего не задали

Когда `lltt` впервые создаёт ваш конфиг (`lltt user init` → `lltt user add`
→ первый `lltt set`), он смотрит на переменные окружения
`LC_ALL`, `LC_MESSAGES` или `LANG` (в этом порядке) и выбирает язык писем
по первой подходящей:

- `ru`, `ru_RU.UTF-8`, `ru_RU` и т. п. — письма на русском;
- `en`, `en_US`, `en-GB` и т. п. — письма на английском;
- любой другой язык (`de`, `fr`, `zh_CN` …) — письма на английском.

Если ни одна из переменных не задана, по умолчанию используется `en`.

Позже вы всегда можете поменять язык явной командой `lltt set language …`
(см. выше).

Локализация работает только на стороне **отправителя** —
то есть ваши письма приходят читателю на вашем языке
(это сознательное упрощение: блоговая платформа,
подписчик готов читать на языке блогера).

### 5.6. Журнал работы

Когда что-то идёт не так с почтой, удобно посмотреть, что `lltt` делал на самом деле. Для этого есть журнал — простой текстовый файл, куда записываются подключения, отправки и ошибки. По умолчанию журнал выключен, чтобы не занимать место на диске.

#### Включить

```sh
lltt set log.level info
```

После этого каждое подключение к почтовому серверу и каждая отправка будут оставлять строчку в журнале. Никакие пароли и сами письма в журнал не попадают.

#### Выключить

```sh
lltt set log.level off
```

Сам файл журнала при этом не удаляется — старые записи остаются, новые не появляются.

#### Где лежит файл

Журнал хранится в подкаталоге `logs` внутри домашнего каталога `lltt`:

```
<домашний каталог>/logs/liveletters.log
```

`<домашний каталог>` — это путь из переменной `LIVELETTERS_HOME`, либо по умолчанию `~/.liveletters/`. Текущее значение показывает команда `lltt doctor`.

#### Как посмотреть записи

Откройте файл в любом текстовом редакторе, либо в терминале:

```sh
tail -f ~/.liveletters/logs/liveletters.log
```

Команда `tail -f` показывает новые строки в реальном времени — удобно, когда синхронизация запущена в другом окне.

Каждая строка содержит дату, уровень, что делали и параметры:

```
2026-06-07T11:08:18.791Z info  imap.connect host=imap.example.org port=993
2026-06-07T11:08:28.977Z error imap.connect error=сервер недоступен
```

#### Уровни детализации

Их шесть, от «молчит» до «пишет вообще всё»:

| Команда | Что пишется |
|---|---|
| `lltt set log.level off` | Ничего (по умолчанию) |
| `lltt set log.level error` | Только сбои и поломки |
| `lltt set log.level warn` | Сбои и подозрительные ситуации |
| `lltt set log.level info` | Обычные действия: «подключился», «отправил» |
| `lltt set log.level debug` | info плюс технические подробности |
| `lltt set log.level trace` | Совсем всё подряд, для разработчиков |

Обычно достаточно `info`. Если инженер просит «дай больше деталей» — переключитесь на `debug` или `trace` и пришлите ему файл журнала.

#### Если файл стал слишком большим

Не нужно чистить руками. Журнал сам хранит не больше трёх архивных файлов по 5 мегабайт каждый (примерно 20 мегабайт максимум). Старые записи удаляются автоматически.

## 6. Ваш первый пост

Посты создаёт команда `lltt post new`. У неё два ключа: `--body-file`
(путь к файлу с текстом) и `--visibility` (уровень видимости). Если
`--body-file` не указан, тело читается из стандартного ввода.

### 6.1. Пост из stdin

```sh
lltt post new
```

После запуска введите текст, завершите ввод клавишей `Ctrl-D`:

```
Привет, это мой первый пост в `lltt`.
Ctrl-D
```

Команда печатает `запись создана: post-…`. Запомните идентификатор
(он понадобится для комментариев и обсуждений).

### 6.2. Пост из файла

Подготовьте файл с текстом:

```sh
cat > ~/lltt-demo/work/post-1.txt <<'EOF'
Сегодня я попробовал `lltt`.
Пока нравится.
EOF
```

Создайте пост:

```sh
lltt post new --body-file ~/lltt-demo/work/post-1.txt
```

### 6.3. Уровни видимости

Доступны два значения:

- `public` — пост виден всем (по умолчанию);
- `friends_only` — пост виден только узкому кругу.

```sh
lltt post new --visibility friends_only --body-file ~/lltt-demo/work/post-1.txt
```

Любое другое значение — ошибка:

```sh
lltt post new --visibility private
# ошибка: ...
```

### 6.4. Пустое тело

Пустой пост создать нельзя:

```sh
echo "" | lltt post new
# ошибка: тело записи пустое
```

## 7. Мои посты

Команда `lltt cu posts` показывает посты текущего пользователя
liveletters. Самый простой запуск:

```sh
lltt cu posts
```

Команда печатает шапку, общий счётчик и сами посты в обратном
хронологическом порядке:

```
посты пользователя: Алиса
постов: 2 (показано: 2)

┌─ пост #post-… от acct_alice
│  visibility: public
│  2026-… UTC
│  …
└─
```

Чтобы увидеть только последние записи, добавьте `--limit`:

```sh
lltt cu posts --limit 1
```

## 8. Подписки и лента

Подписка связывает ваш блог с чужим адресом блога. Все посты,
опубликованные там, будут приходить вам по почте.

### 8.1. Подписаться

```sh
lltt sub bob@blog.example.org
```

Команда печатает, на какой адрес будут приходить письма, и завершается.
Подписаться можно на любой корректный адрес электронной почты.

### 8.2. Посмотреть подписки

```sh
lltt sub list
```

Команда печатает две секции: «подписан на» (ваши подписки) и
«мои подписчики» (кто подписан на ваш блог). Изначально обе секции
пустые.

В сетевом обмене подписчик определяется почтовым адресом доставки.
`account_id` из файла идентичности по почте не передается и не используется
для доверия.

### 8.3. Отписаться

```sh
lltt sub rm bob@blog.example.org
```

Команда печатает `отписан от <адрес>` и завершается.

### 8.4. Лента подписок

```sh
lltt feed
```

Команда показывает посты ресурсов, на которые вы подписаны. Собственные
посты в эту ленту не попадают; их смотрят через `lltt cu posts`.
Порядок обратный хронологический: новые записи сверху.

Ограничить выдачу:

```sh
lltt feed --limit 20
```

### 8.5. Ошибки

```sh
lltt sub
# ошибка: `lltt sub` требует адрес блога

lltt sub add
# ошибка: ...
```

Подписаться можно только на корректный адрес электронной почты — без
собаки команда откажется работать.

## 9. Комментарии

Команда `lltt comment new` добавляет комментарий к посту. Обязательный
аргумент — `--post`, идентификатор поста.

```sh
lltt comment new --post post-1780677869022
```

Команда читает тело из stdin (или из `--body-file`); в конце — клавиша
`Ctrl-D`:

```
Отличный пост!
Ctrl-D
```

Команда печатает `комментарий создан: comment-…`.

### 9.1. Вложенные ответы

Чтобы ответить на конкретный комментарий, передайте его идентификатор
через `--parent`:

```sh
lltt comment new --post post-1780677869022 --parent comment-1780677869100 --body-file ~/lltt-demo/work/reply.txt
```

### 9.2. Видимость комментариев

Как и у постов, у комментариев есть флаг `--visibility` (`public` или
`friends_only`); по умолчанию — `public`.

### 9.3. Ошибки

Если указать несуществующий идентификатор поста, команда завершится
с ошибкой. Пустое тело также недопустимо.

## 10. Тред (обсуждение)

Команда `lltt thread` показывает пост и все его комментарии в виде
дерева.

```sh
lltt thread post-1780677869022
```

Команда печатает запись, счётчик комментариев и обсуждение. Корневые
комментарии выводятся точками, ответы — со стрелкой и отступом:

```
┌─ пост #post-… от acct_alice
│  visibility: public
│  …
└─

комментарии: 2

  • acct_bob (comment-1)
        Здравствуйте!
    ↳ acct_alice (comment-2)
          И вам того же!
```

Если комментариев нет, команда напишет `(нет комментариев)`.
Несуществующий идентификатор поста — ошибка.

## 11. Входящая почта

Команда `lltt inbox` управляет входящими письмами. У неё три
подкоманды: `import`, `list`, `show`.

### 11.1. Импорт `.eml`-файлов

Если у вас есть файл с письмом в формате `.eml` (например, скачанный
из почтового клиента), его можно импортировать вручную:

```sh
lltt inbox import ~/Downloads/letter.eml
```

Команда печатает результат по каждому файлу и итоговую сводку.
Письмо проходит через полный конвейер разбора: если оно корректное
и адресовано вам, оно появится в ленте.

Импортировать можно сразу несколько файлов:

```sh
lltt inbox import a.eml b.eml c.eml
```

### 11.2. Список входящих

```sh
lltt inbox list
```

Команда печатает таблицу из трёх колонок: `message_id`, `status`,
`preview`. По умолчанию — последние 20 писем. Изменить размер
выдачи:

```sh
lltt inbox list --limit 50
```

Отфильтровать по статусу:

```sh
lltt inbox list --status applied
```

Допустимые статусы: `applied`, `duplicate`, `replay`, `unauthorized`,
`invalid`, `malformed`.

### 11.3. Полное тело письма

```sh
lltt inbox show "<test-1@example.test>"
```

Команда печатает идентификатор, статус и полный текст письма.
Идентификатор берётся из заголовка `Message-ID` и обычно заключён
в угловые скобки.

## 12. Исходящая очередь

Каждое действие — публикация поста, добавление комментария, подписка —
порождает событие в исходящей очереди. Эти события ожидают отправки
по электронной почте подписчикам.

```sh
lltt outbox list
```

Команда печатает счётчик и таблицу с колонками `event_id`, `event_type`,
`resource_id`. Это read-only-команда: посмотреть, но не отправить.

Чтобы очистить очередь, нужно настроить SMTP (см. раздел 5.3) и
выполнить `lltt sync push` (см. раздел 14).

## 13. Краткий статус и диагностика

### 13.1. `lltt status`

Пять строк с агрегированными счётчиками: посты, комментарии,
отложенные события, исходящие, время последней активности. Удобно
для быстрой оценки.

### 13.2. `lltt doctor`

Девять строк: общее состояние («здоров» или «деградирован») и
счётчики входящей почты по категориям. Состояние «здоровье»
определяется автоматически: если есть отклонённые, неавторизованные
или повреждённые письма — оно «деградирован».

Расширенный режим:

```sh
lltt doctor --verbose
```

Добавляет три секции: последние отложенные события, список
идентичностей и размер таблиц базы данных в байтах.

## 14. Сетевая синхронизация

Команда `lltt sync` обменивается данными с другими узлами по
электронной почте: сначала забирает входящие письма, затем отправляет
исходящие. Перед первой попыткой необходимо задать настройки почты
(раздел 5.3).

Письмо LiveLetters является обычным текстовым письмом: в почтовом
клиенте виден человекочитаемый текст записи или служебного события.
В конце тела находится служебный блок LiveLetters, который нужен
`lltt` для применения события.

```sh
lltt sync
```

Если нужно выполнить только одну половину цикла, используйте явные
подкоманды.

### 14.1. Забрать новые письма

```sh
lltt sync pull
```

Команда подключается к IMAP-серверу, забирает все письма, которые
появились после прошлого запуска и помечены заголовком
`X-LiveLetters-Protocol: v1`, прогоняет их через конвейер разбора и
сохраняет результат. Обычные письма без этого заголовка не скачиваются
целиком. Каждое применённое письмо появится в `lltt inbox list` и, если
ресурс есть в ваших подписках, в `lltt feed`.

Если IMAP-сервер не поддерживает поиск по этому заголовку, `lltt`
использует запасной путь: сначала загружает только заголовки новых
писем, а полное тело скачивает только для писем LiveLetters. На
некоторых IMAP-серверах (mail.ru) и поиск по заголовку, и
выборочная загрузка заголовков отвергаются — тогда `lltt` загружает
всё тело письма и ищет нужный заголовок локально. Это чуть дороже
по трафику, но работает на любом сервере.

При **самом первом** запуске `lltt sync pull` (когда в локальной БД
ещё нет курсора) команда запрашивает у IMAP минимальный UID писем
за последние `imap.initial_lookback_days` суток (по умолчанию `1`)
через `UID SEARCH SINCE <дата>` и начинает с этого UID. Это
защищает от перебора всей истории ящика на первом запуске. После
первого запуска настройка больше не действует: sync работает по
сохранённому курсору.

Повторный запуск сразу после успешного ничего не заберёт —
`lltt` запоминает, до какого сообщения уже прочитал.

### 14.2. Отправить исходящие

```sh
lltt sync push
```

Команда перебирает записи в `outbox` и для каждой находит подписчиков
блога, после чего отправляет им письмо. Если отправка на всех
подписчиков прошла без ошибок, запись удаляется из очереди.

Если у блога пока нет подписчиков, запись остаётся в очереди —
это нормально: подписчики могут появиться позже.

### 14.3. Подтянуть прошлое

```sh
lltt sync backfill --days 30
```

Разовая команда: подтянуть письма за последние N суток, **не
сдвигая** основной sync-курсор. Полезна, если при первом запуске
`imap.initial_lookback_days` был слишком мал.

По умолчанию `--days=30`. Команда открывает отдельное IMAP-соединение,
выполняет `UID SEARCH SINCE <дата>`, скачивает найденные письма и
прогоняет их через конвейер разбора, но **не** сохраняет новый курсор.
После выполнения `lltt sync pull` продолжает работать с прежнего
места.

### 14.4. Типичные ошибки

```sh
lltt sync pull
# ошибка: настройки почты для alice отсутствуют; заполните почтовые секции в черновике `lltt user init alice` или используйте `lltt set smtp.host …
```

Подобное сообщение означает, что нужный блок настроек ещё не
заполнен. Сверьтесь с разделом 5.3.

Если IMAP- или SMTP-сервер недоступен, команда напечатает класс
ошибки (`Imap`, `Smtp`, `Network` и т. п.) и причину. Чтобы разобраться в деталях, включите журнал командой `lltt set log.level info` и запустите синхронизацию ещё раз — в файле `<домашний каталог>/logs/liveletters.log` останется полная картина: адрес сервера, ответы, ошибки.

## 15. Полный сценарий: от пустого каталога до публикации

Этот сценарий собирает всё в один непрерывный пример. Запускайте
команды по порядку в чистом терминале.

```sh
# 1. Готовим каталог и инициализируем
export LIVELETTERS_HOME="$HOME/lltt-demo"
mkdir -p "$LIVELETTERS_HOME"
lltt init

# 2. Проверяем, что всё на месте
lltt user list

# 3. Создаём черновик идентичности, правим его в редакторе и добавляем
lltt user init alice
nano "$LIVELETTERS_HOME/drafts/alice.toml"
lltt user add alice
lltt cu alice

# 4. Проверяем состояние и профиль пользователя
lltt status
lltt doctor
lltt set nickname      alice
lltt set email_address alice@blog.example.org

# 5. Пишем первый пост
cat > "$LIVELETTERS_HOME/work/post-1.txt" <<'EOF'
Привет, мир!
Это мой первый пост в `lltt`.
EOF
lltt post new --body-file "$LIVELETTERS_HOME/work/post-1.txt"

# 6. Смотрим свои посты
lltt cu posts

# 7. Подписываемся на чужой блог
lltt sub bob@blog.example.org
lltt sub list

# 8. Смотрим очередь — там появилось событие подписки
lltt outbox list

# 9. Если почту не заполнили в черновике, задайте её через `lltt set`
lltt settings

# 10. Выполняем полный цикл синхронизации при заполненных настройках почты
lltt sync
lltt inbox list

# 11. Пишем комментарий к своему последнему посту
POST_ID=$(lltt cu posts --limit 1 | sed -n 's/^.*#\(post-[0-9]*\).*$/\1/p' | head -1)
lltt comment new --post "$POST_ID" --body-file "$LIVELETTERS_HOME/work/post-1.txt"

# 12. Смотрим тред
lltt thread "$POST_ID"

# 13. Итоговая диагностика
lltt doctor --verbose
```

## 16. Шпаргалка по командам

|---|---|
| `lltt init` | Создать домашний каталог с нуля |
| `lltt init --force` | Инициализировать непустой каталог без удаления файлов |
| `lltt cu` | Показать имя текущего пользователя |
| `lltt cu show` | Показать сведения о текущей идентичности |
| `lltt cu <имя>` | Переключить текущего пользователя |
| `lltt user list` | Показать все идентичности |
| `lltt user init <имя>` | Создать черновик идентичности |
| `lltt user init <имя> --force` | Перезаписать черновик |
| `lltt user show <имя>` | Показать сведения об идентичности |
| `lltt user add <имя>` | Добавить идентичность из стандартного черновика |
| `lltt user add <имя> --from <файл>` | Добавить идентичность из другого TOML-файла |
| `lltt user rm <имя> --yes` | Удалить идентичность |
| `lltt settings` | Показать все настройки |
| `lltt settings set <ключ> <значение>` | Изменить одну настройку |
| `lltt set <ключ> <значение>` | То же, что `lltt settings set`, короткая форма |
| `lltt set log.level info` | Включить журнал работы |
| `lltt set log.level off` | Выключить журнал работы |
| `lltt post new` | Создать пост (тело из stdin) |
| `lltt post new --body-file <файл>` | Создать пост из файла |
| `lltt post new --visibility <уровень>` | Пост с уровнем видимости |
| `lltt comment new --post <id>` | Добавить комментарий к посту |
| `lltt comment new --parent <id> --post <id>` | Ответить на комментарий |
| `lltt cu posts` | Показать свои посты |
| `lltt cu posts --limit N` | Показать последние N своих постов |
| `lltt feed` | Показать ленту подписок |
| `lltt feed --limit N` | Показать последние N постов подписок |
| `lltt thread <post_id>` | Показать пост и обсуждение |
| `lltt sub <адрес>` | Подписаться на блог |
| `lltt sub list` | Показать подписки и подписчиков |
| `lltt sub rm <адрес>` | Отписаться |
| `lltt inbox import <файл>…` | Импортировать `.eml`-файлы |
| `lltt inbox list` | Показать последние письма |
| `lltt inbox list --status <категория>` | Фильтр по статусу |
| `lltt inbox list --limit N` | Ограничить размер выдачи |
| `lltt inbox show <id>` | Полное тело одного письма |
| `lltt outbox list` | Показать неотправленные события |
| `lltt sync` | Забрать входящие и отправить исходящие |
| `lltt sync pull` | Забрать новые письма с IMAP |
| `lltt sync push` | Отправить исходящие через SMTP |
| `lltt sync backfill --days 30` | Разовый заброс: подтянуть прошлое, не сдвигая курсор |
| `lltt set imap.initial_lookback_days 7` | Окно в сутках для самого первого sync |
| `lltt status` | Краткий отчёт о состоянии |
| `lltt doctor` | Диагностика состояния |
| `lltt doctor --verbose` | Расширенная диагностика |

## 17. Что дальше

Документ охватывает все команды `lltt`, доступные в текущей сборке.
Если во время прохождения что-то работает не так, как описано,
проверьте три вещи:

- правильно ли задана переменная `LIVELETTERS_HOME`;
- выбрана ли нужная идентичность (`lltt cu`);
- нет ли сообщения об ошибке в самом конце вывода команды.

Когда все шаги проходят без ошибок, вы готовы к ежедневной работе
с `lltt`: пишите посты, подписывайтесь на других, обменивайтесь
комментариями и периодически запускайте `lltt sync`, чтобы забирать
новые записи и доставлять свои записи подписчикам.
